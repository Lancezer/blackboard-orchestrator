# 功能说明

## 用途

在本机 Codex CLI 与 DeepSeek Harness（DSH）WebUI 之间交接用户指定的工作。两端会话都能发起交接，并可指定新建对方会话或使用同一任务中的已有会话。任务路径由用户要求和 Agent 决定；目标会话结束后没有默认的自动回调。

例如，可以让 DSH 会话 A 唤起 Codex 会话 B 规划；用户批准后让 B 唤起新 DSH 会话 C 实现，C 再唤起 B 审查，最后由 B 唤起 A 报告。也可以只进行 A → B 一次交接。

## 使用入口

- Codex：自然语言或 `$to-dsh`，由模型调用 `delegate_to_dsh`。
- DSH：自然语言或 `/to-codex`，由模型调用 `delegate_to_codex`。
- `blackboard_sessions`：查看任务 ID、黑板和参与会话 ID。
- `blackboard_read`：读取当前任务的黑板与最新交接要求。
- `blackboard_options`：查询两端模型、推理强度和会话权限选项。
- `blackboard_set_permission`：按用户明确要求调整参与会话权限。

技能提供模型可读的调用说明；显式选择技能本身不会绕过模型或直接执行交接。两端入口登记请求后，源会话结束当前回合，控制器再唤起目标。Agent 应在交接要求中写明用户提出的后续目标，并使用任务 ID 继续关联参与者。

在 DSH 发起新 Codex 会话时，工具会尝试打开本机终端里的原生 TUI。已经存在的会话按其 ID 恢复；没有图形终端时可用 `node src/cli.mjs tui <任务ID>` 手动打开。

## 计划、工作区与 Git

代码修改须先得到用户对计划的明确批准；只读规划可提前进行。用户可在任一参与会话批准，Agent 负责如实记录。任务发生重要范围变化或涉及新项目时，应先获得用户同意。

交接工具可指定目标工作区。DSH 会话的沙箱工作区以其创建时的原生工作区为准，不匹配时需新建会话或由用户通过原生机制授权。控制器不会因改变目录而自动扩大权限。

涉及代码的任务，每次跨端交接前均检查源和目标 Git 工作区；有未提交或未忽略的未跟踪文件时停止。非 Git 目录支持只读工作，不支持修改代码的交接。Agent 可自行决定建分支或提交；控制器不会自动暂存、提交、合并或推送。不同任务可使用同仓库的独立 worktree 并发。

## 文件位置

单项目任务位于实际项目的 `.codex-dsh/tasks/<任务ID>/`。多项目任务位于 `~/.local/share/blackboard-orchestrator/tasks/<任务ID>/`。已批准的新项目使任务变成多项目时，控制器在会话停稳后迁移目录并保留旧路径引用。无法迁移时停止并报告。

`HANDOFF.md` 记录任务状态、参与会话和文档入口；每次交接要求与可观察到的最终结果另存文件。控制器和两端适配器使用用户目录下的共同运行位置；安装时把 `.codex-dsh/` 加入用户级 Git 忽略文件，不改项目 `.gitignore`。

本地黑板不是模型隐私屏障：模型可能收到完成任务所需的内容。控制通知传递任务 ID、会话 ID 和路径等元数据，不直接作为完整业务上下文传递。

## 模型与权限

在 `config.json` 分别配置 Codex 和 DSH 模型及推理强度；空值继承原生默认。对话也可为一次交接指定型号。DSH 的临时模型选择结束时尽力恢复，期间若用户已自行切换则不覆盖。

权限列表来自两端原生服务。用户可明确要求调整当前或任务参与会话的权限；任务内默认临时生效，结束时尽力恢复，用户要求持久生效时保留。若 DSH 原权限是无法通过预设重新选择的 `custom`，自动恢复可能失败并被报告。

Codex 线程设置从下一回合生效；用户要求调整并继续时在同一线程接续。DSH 权限更改影响之后的受限工具调用，不会改变已经启动的进程。原生审批、文件沙箱和用户可手动调整的设置仍然有效。

## 控制器与故障处理

首次工具调用自动启动控制器，空闲时常驻但不发起模型请求。没有可用 DSH Web Host 时会启动一个；停止控制器不会关闭该 Host。插件关闭后，工具尝试利用已知 Host 连接通过原生插件管理接口启用；无法启用或需要重启时提示用户处理。

超时、目标繁忙、权限不可用、工作区不干净或服务异常时，任务会阻断并保留材料。控制器重启不自动重放未知操作。人工检查会话、后台作业和工作区后，可以使用 `resume <任务ID> --retry` 恢复仍有待处理交接的任务。

同一任务在两端之间协作式串行；用户跨端接手或手改代码前先暂停并确认停稳。其他独立任务可并发。共享端口、数据库和 GPU 不做全局锁定，冲突只能尽力发现并由用户处理。
